Análise do setup atual e recomendações práticas para extrair mais do Claude Code.

## 1. Criar CLAUDE.md Global (~/.claude/CLAUDE.md)

Por que: Preferências pessoais que valem para TODOS os projetos.
Hoje, ao abrir outro projeto, o Claude não sabe nada sobre você.

Benefício: Qualquer projeto novo já terá suas preferências carregadas.

---

## 2. Configurar Permissões Inteligentes (settings.json)

Por que: Hoje você recebe muitos prompts de "Allow?" para operações seguras.
Libere as operações de rotina (git, dotnet, npm, docker compose, ls, mkdir).

Benefício: Fluxo sem interrupções para operações de build, git e dev.

---

## 3. Configurar Hooks

Por que: Hooks executam comandos automaticamente antes/depois de ações do Claude.
Substituem lembretes manuais.

Hooks recomendados:
- Auto-lint no frontend após edição de .ts
- Build check no backend após edição de .cs
- Aviso sobre arquivos grandes sendo lidos (>500 linhas)

Benefício: Feedback automático sobre erros de build e lint sem precisar pedir.

---

## 4. Usar Memory de Forma Estratégica

Por que: Memórias persistem entre sessões. Hoje está vazio.

O que salvar:
- Perfil do desenvolvedor (preferências, stack, estilo)
- Decisões arquiteturais e seus motivos
- Informações não-óbvias do projeto

Ação: Peça explicitamente "lembre que..." ou "salve que decidimos..."

---

## 5. Dominar o Fluxo de Trabalho

### 5a. Quando usar Plan Mode

| Cenário                          | Usar Plan? |
|----------------------------------|-----------|
| Criar feature nova               | Sim       |
| Refatorar módulo existente        | Sim       |
| Fix de bug pontual                | Não       |
| Atualizar docs/CLAUDE.md          | Não       |
| Decisão de arquitetura            | Sim       |

Dica: Comece tarefas complexas com "planeja..." — o Claude pesquisa o codebase e apresenta o plano antes de executar.

### 5b. Quando usar Subagents

| Cenário                            | Subagent?               |
|------------------------------------|------------------------|
| Pesquisar algo no codebase          | Sim (Explore)          |
| Editar 1-3 arquivos                | Não                    |
| Editar 10+ arquivos similares       | Sim (Agent + worktree) |
| Investigar bug em área desconhecida | Sim (Explore)          |
| Rodar testes e analisar resultado   | Sim (geral)            |

### 5c. Gerenciamento de Contexto

| Ação        | Quando                                              |
|-------------|-----------------------------------------------------|
| /compact    | Sessão longa, Claude começa a "esquecer"            |
| Sessão nova | Muda de área completamente (backend → frontend)     |
| Skills      | Sempre que existir um — evita re-explicar o contexto |

Regra de ouro: Se você está repetindo a mesma instrução pela 2a vez, deveria ser um skill ou estar no CLAUDE.md.

### 5d. Atalhos Úteis

| Atalho      | Ação                                          |
|-------------|-----------------------------------------------|
| Esc         | Cancela resposta em andamento                  |
| Ctrl+J      | Aceita edição sugerida                         |
| Tab         | Autocompleta caminhos de arquivo               |
| ! comando   | Roda comando no terminal dentro da conversa    |
| / + nome    | Invoca skill                                   |

## 6. Dicas para CLAUDE.md Mais Eficaz

O que funciona bem:
- Regras absolutas numeradas com "nunca/sempre"
- Tabela de skills com "quando usar"
- Instrução de auto-invocação de skills

O que adicionar:
- Seção "Quando em Dúvida" — árvore de decisão para casos ambíguos
- Seção "Anti-patterns" — erros comuns para evitar

---

## 7. Plugins e MCP — Aproveitando Melhor

Plugins ativos e como usar:

| Plugin            | Trigger                        | Dica                                           |
|-------------------|--------------------------------|------------------------------------------------|
| context7          | Perguntar sobre lib/framework  | "consulte a doc do Angular 21 sobre signals"   |
| context-mode      | Outputs grandes (logs, builds) | Funciona automaticamente                        |
| interface-design  | UI/dashboard/admin             | "critique minha UI" ou "revise o design"        |
| frontend-design   | Criar componentes visuais      | Ativado automaticamente ao criar UI             |
| security-guidance | Revisar segurança              | Combine com /security-review                    |

Plugin recomendado para adicionar:
- GitHub MCP Server — interagir com PRs, issues e repos diretamente
